# Transformers from Scratch: Encoder–Decoder Lab

An educational Jupyter notebook implementing a Transformer encoder–decoder using TensorFlow/Keras tensor operations and custom layers. It includes a reproducible synthetic sequence-to-sequence dataset, separate training-only vocabularies, scaled dot-product attention, multi-head attention, sinusoidal positional encoding, padding and causal masks, custom encoder/decoder blocks, training, greedy decoding, test evaluation, and actual attention visualizations.

## Environment

- Recommended: Python 3.10–3.12
- TensorFlow 2.16–2.19 (choose the build supported by your Python/platform)
- CPU is supported; GPU acceleration is optional.
- Internet is not needed to generate the synthetic data. Interactive graphs are written locally as HTML files. Viewing Plotly output inside Jupyter does not require separate data downloads.

Create a virtual environment, install the dependencies, launch Jupyter, and open `Transformer_From_Scratch_Encoder_Decoder.ipynb`:

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# macOS/Linux: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip install jupyter
jupyter notebook
```

Google Colab can also run the notebook; select a GPU runtime if available and desired.

## Execution notes

Run cells in order. The default synthetic dataset has 13 task types and 10,400 examples (`examples_per_task=800`). The default model is intentionally smaller than the original Transformer base setup (`d_model=64`, four heads, one encoder layer, one decoder layer) so a CPU run remains plausible. Increase the width, depth, dataset size, and number of epochs only after validating the pipeline.

The notebook trains from scratch and saves the best checkpoint by validation loss. It then performs greedy autoregressive generation on the full held-out test split. Exact scores depend on hardware, library versions, random operations, and training progress. Do not interpret synthetic-task results as general-purpose language understanding.

The optional ablation experiments and small-batch overfit check are implemented but disabled by default. Set `RUN_ABLATIONS = True` or `RUN_OVERFIT_SANITY_CHECK = True` in the corresponding cells to run them.

## Output structure

The notebook creates `transformer_from_scratch_outputs/` in the current working directory:

```text
transformer_from_scratch_outputs/
├── images/                 # PNGs when generated by a Matplotlib/static export path
├── plots_html/              # Interactive Plotly visualizations
├── metrics/                 # training history, test metrics, predictions, parameter counts
├── checkpoints/             # best-validation model weights
├── model/                   # source/target vocabularies and model config
├── data/                    # synthetic dataset and split summary
└── logs/                    # run summary
```

Plotly figures are saved as HTML. Static Plotly PNG export is optional and depends on an available rendering backend. No evaluation results are included as fabricated defaults; metrics are produced by actually running the notebook.

## Model implementation

The model does not use Hugging Face Transformers, a pretrained model, `keras.layers.MultiHeadAttention`, or a ready-made Transformer architecture. Query/key/value projections, scaled dot-product attention, head splitting/recombination, positional encoding, masks, encoder/decoder layers, and output projection are explicitly implemented.
